# BLOCK-96 — контекст разработки для Codex

Состояние обсуждения: 26.11.2026. Этот файл — переносимый конспект чата, а не дословный экспорт переписки. Все факты аудита относятся к контрольной v73; повторно проверить их на текущем checkout. Исследовательские и архитектурные предложения не являются уже реализованными функциями.

## 1. Цель и решения владельца
Block-96 — 2D браузерная игра с рейдами, убежищем, лутом, городом, транспортом, зданиями с интерьерами, населением и фракциями. Приоритет мобильной игры. Владелец предоставил два видеореференса и пояснил: графика и ориентация камеры там отличаются, но показанный результат хочется видеть. Принятое в обсуждении направление: перенести атмосферу и визуальную детализацию на существующую камеру, не менять движок без согласования. Владелец подтвердил: «склад не теряется». Сохранение склада — обязательное правило, не дефект.

## 2. Хронология обсуждения (конспект)
1. Пользователь: «аудит .» — запрос проверки v73. Первичный аудит выявил непереносимый тестовый harness, падающие проверки ППС, устаревшие описания и риски производительности. Полный браузерный прогон не проводился. Первоначальный вывод о поломке ППС был слишком сильным.
2. Пользователь: «склад не теряется. всё остальное проверь предложи варианты решения и оптимизации». Уточнение закреплено. Углублённый аудит (в приложенном DOCX) показал ложный выбор постового вместо патруля, связность дорожной сети с мостами и 0 конфликтов зданий с дорогами по runtime-аудиту. Главные риски — boot, память геометрии, тесты, миграции сохранений и непроверенная мобильная графика/доступность входов.
3. Пользователь попросил исследовать новые игры жанра и AAA, совпадения ошибок и технически корректные решения. Сопоставлены ZERO Sievert, Escape from Duckov, Project Zomboid, Cataclysm: DDA, S.T.A.L.K.E.R., Assassin’s Creed Unity, Cyberpunk 2077, Horizon Zero Dawn и Suroi. Вывод: адаптировать проверенные принципы, а не копировать чужой движок. См. раздел 5.
4. Пользователь приложил два видео: «Здесь графика другая. И ориентация камеры. Но это то чего хочется видеть». Предложены эталонный квартал, текстуры износа, интерьеры, свет, тени, растительность, погода, эффекты боя и анимации. Точный движок референсов не установлен. Художественный стиль и реализация требуют утверждения владельцем.
5. Пользователь попросил поэтапный план обновлений через Deep Research. Исследование было запущено; отдельный готовый результат в доступной переписке не представлен. Дорожная карта в данном пакете — синтез доступного аудита и обсуждения, не выдаётся за завершённый отчёт Deep Research.
6. Обсуждены режимы ChatGPT. Рекомендация: ChatGPT для архитектуры/планирования и Deep Research для источников; Codex + Git для правок и тестов; реальное устройство для проверки графики. Предложены AGENTS.md и план v74–v80.
7. Пользователь запросил начать работу через Codex Tasks. Команды запуска удалённой среды оказались недоступны. Работа Codex не была запущена, исходники не были изменены. Подготовлено задание v74.
8. Пользователь попросил собрать чат в архив или в ссылочный контекст для Codex. Подготовлен этот пакет, инструкции и исходные материалы.

### Подтверждённые проблемы / риски
- `tests/behavior.test.js:58–62`: выбор ППС через `!q.post` не гарантирует патруль. В диагностике выбран одиночный `pps_rpk` с `q.post === false`; настоящий патруль из 3 участников при корректном выборе переходил в WARN_HOLSTER. Не переписывать AI на основании четырёх ложных/зависимых падений; проверить полный сценарий и seed.
- `tests/harness.js`: исторический абсолютный root; нет стандартного npm test, многократные дорогостоящие boot. Полный проход gangs/extras не подтверждён. Разделить unit, fixtures, интеграцию и smoke.
- `game.js` loadSave/persist: загрузка только v1, слабая нормализация, ошибки storage подавляются. Риск молчаливой потери прогресса при будущих изменениях. Склад после смерти работает согласно правилу.
- Геометрия: spatial grid уже есть. Количество объектов повышает цену boot и памяти; оценивать профиль heap и объединение совместимых статических сегментов/компактное хранение, не менять коллизии вслепую.
- `modules/vision.js`: полноразмерная маска Canvas и композиция несколькими проходами; предполагаемый, а не доказанный мобильный hotspot. Проверить на телефоне.
- `README.md` и PDF отстают от v73. Старые имена файлов, размеры города и 15 районов/потеря склада в PDF — исторические данные, не спецификация.
- DOM `innerHTML`: потенциальный риск при импорте/модах/сетевых данных; доказанного XSS нет. Для недоверенного текста использовать безопасные DOM API, не вводить CSP, ломающую загрузку, без тестов.

## 4. Архитектурные ориентиры
Сохранить Canvas 2D и существующие модули до доказанной необходимости иной технологии. Сначала измерения, затем минимальная правка. Потенциальные компоненты: GeometryStore (совместимый API wallsNear/rayWall), ChunkManager (детерминированные ID и seed), Navigation (глобальный граф + локальные маршруты, разные профили агента/машины), AI Scheduler (раздельные частоты при необходимости), SaveManager (parse/normalize/migrate/backup). Не считать эти имена существующими файлами.

Симуляция NPC должна сохранять здоровье, цели, принадлежность, инвентарь и состояние при смене LOD. Дальний мир не должен переставать существовать. Визуальная маска не должна подменять точные игровые проверки видимости. При lazy interiors идентичность планировки и состояние обысканного контейнера сохраняются. Мосты и входы проверять физическим проходом, не только графом. Чанки 64 м, уровни 50/150/400 м и частоты 60/15/2 Гц обсуждались как экспериментальные примеры, не требования.
